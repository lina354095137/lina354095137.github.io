# 硬件项目问题跟踪助手

硬件NPI项目每天产生问题：评审会拍板要改的、试产暴露的、测试挂掉的、物料来料不良的。这款技能把它们收进一张Excel台账，管到闭环，并在阶段切换时做门禁检查——数据说了算放不放行。

## 快速开始

### 阶段1：生成问题台账

```
python3 scripts/issue_tracker.py init --project 智能插座X1 --stage DVT
```
生成 `{项目名}_问题台账.xlsx`，12列结构（问题ID/阶段/来源/描述/严重度/责任人/提出日期/目标关闭日/状态/验证结论/关联风险ID/备注）。

### 阶段2：批量导入问题

评审会或试产结束后，问题按行写进txt（一行一条，用|分隔），导入：

```
python3 scripts/issue_tracker.py add --ledger 智能插座X1_问题台账.xlsx --from-txt DVT问题清单.txt --source 试产
```
行格式：`问题描述 | 严重度 | 责任人 | 阶段`（严重度之后可省略，默认C类/当前阶段）。 **异常隔离** ：格式错的行跳过并逐行告诉你原因（比如"D类不认识，只认A类/B类/C类"），其余照常导入。

### 阶段3：阶段门禁检查

进下一阶段前（比如DVT要转PVT）：

```
python3 scripts/issue_tracker.py gate --ledger 智能插座X1_问题台账.xlsx --stage DVT
```
对照 `templates/gate-rules.yaml` 的出口准则逐类检查关闭率：

- ✓/✗ 逐类显示：关闭率 vs 门槛

- 结论：**建议进入下一阶段**  或 **暂缓，先关闭这N条** （列出到问题级）

- 默认标准：EVT→DVT A类100%/B类80%；DVT→PVT A类100%/B类90%/C类60%；PVT→MP A类100%/B类100%/C类80%。按公司标准改yaml即可。

### 阶段4：统计报告

周会前跑一份：

```
python3 scripts/issue_tracker.py report --ledger 智能插座X1_问题台账.xlsx
```
输出：总体关闭率（1位小数）、按严重度/阶段/责任人切片、**逾期未关闭清单** （目标日期已过还没关的，标逾期天数）、互推引导。

## 触发方式

| 用户说 | 做什么 |
|---|---|
| 建问题台账 / 开始跟踪问题 | init |
| 问题批量导入 / 评审问题登记 | add --from-txt |
| 能不能进下一阶段 / 门禁检查 / 阶段放行 | gate |
| 问题统计 / 关闭率 / 周会报告 | report |
| 谁的问题最多 / 逾期有哪些 | report，重点解读对应切片 |

## 示例对话

**用户** ：试产完了一圈问题，帮我登记下，然后看DVT能不能过
**助手** ：让用户把问题列成txt（给格式模板）→ add导入（假设6成功1跳过）→ gate --stage DVT → 输出"A类50%未达门槛100%，暂缓进PVT，先关I004高温断连"这样的结论

**用户** ：周会要问题报告
**助手** ：report → 33.3%关闭率、逾期清单点名、责任人分布（张工2条最多），直接可贴会议材料

## 数据与文件约定

- 工作目录：`data/issue_trackers/`（台账Excel和报告在这里）

- 文件命名：`{项目名}_问题台账.xlsx` / `{项目名}_问题跟踪报告.txt`

- 严重度三档：`A类`（阻塞功能/安全/认证/出货）/ `B类`（影响性能可靠性体验）/ `C类`（一般与优化）

- 状态五档（只用这5个词）：`待分析` / `整改中` / `待验证` / `已关闭` / `挂起`

- 已关闭必须填验证结论（怎么验证通过的）；挂起要有备注原因

## 与技能族联动

- **硬件开发风险管理助手** ：同类问题≥3次=系统性问题，去登记为风险（问题ID填进风险备注，问题的"关联风险ID"列填风险ID，双向可追溯）

- **硬件项目排期助手** ：checkpoint评审产出的议题落地为问题清单；门禁未过影响里程碑时回排期调整

- **智能硬件采购业务助手** ：物料类问题涉及换料询价时用
