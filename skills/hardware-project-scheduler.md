# 硬件项目排期助手

## ⚠️ 执行流程清单（必须按顺序执行，不可跳过）

**AI在每次生成排期前，必须按以下顺序逐步执行，每步完成才能进入下一步。** **脚本层有硬校验，跳过任何一步都会导致生成失败。**

| 步骤 | 必须动作 | 禁止动作 | 脚本校验 |
|---|---|---|---|
| **Step 1** | 按引导问卷收集6项参数，向用户展示参数清单并确认 | 在参数不完整时生成；自己编参数不问用户 | `--params-confirmed`必填，不传则拒绝生成 |
| **Step 2** | 向用户展示Excel与飞书多维表格对比表，明确询问"选哪种格式？" | 在用户未选择输出格式前调用脚本 | `--format-confirmed`必填，不传则拒绝生成 |
| **Step 3** | 计算排期数据（工时、工期、日期、风险、评审项） | 跳过计算直接用示例数据 | validate_input校验字段完整性 |
| **Step 4** | 调用脚本生成文件，传齐 `--format-confirmed` 和 `--params-confirmed` | 省略任一必填参数 | 脚本正常执行 |
| **Step 5** | 输出后询问"要不要调整某个阶段的工时分配？" | 输出后直接结束对话 | 脚本输出末尾强制打印Step 5提醒 |

### 强制触发规则

```
触发条件：用户发起排期请求
必须动作：按引导问卷逐项收集6项参数，向用户展示参数清单表格并确认
禁止动作：在用户未确认参数前调用generate_excel.py；自己编参数不问用户
脚本校验：--params-confirmed 参数必填，不传则报错退出

触发条件：用户已确认排期参数
必须动作：向用户展示Excel与飞书多维表格对比表，询问"选哪种格式？"
禁止动作：在用户未选择输出格式前调用generate_excel.py
脚本校验：--format-confirmed 参数必填，不传则报错退出

触发条件：AI调用generate_excel.py
必须动作：传齐 --format-confirmed 和 --params-confirmed 两个参数
禁止动作：省略任一参数

触发条件：Excel生成成功
必须动作：向用户输出文件后，询问"要不要调整某个阶段的工时分配？"
禁止动作：输出后直接结束对话
脚本校验：脚本输出末尾强制打印Step 5提醒
```
### 防偷懒机制说明

本skill在脚本层（generate_excel.py）设置了三道硬校验，AI无法绕过：

1. **`--params-confirmed`** ：强制AI先向用户确认6项参数（项目名称/产品类型/复杂度/团队/开始日期/结束日期）

2. **`--format-confirmed`** ：强制AI先询问用户选Excel还是飞书多维表格

3. **Excel参数确认清单** ：项目概览页底部打印AI使用的6项参数，用户打开Excel第一眼就能核对——如果AI编了参数，用户立刻能发现

即使AI读SKILL.md不仔细跳过了文字流程，脚本也会拒绝运行并报错引导。

### 用户说"默认"时的处理

如果用户说"默认"/"都行"/"你看着办"：

- 按Excel生成（零门槛，人人可用）

- 但仍需传 --format-confirmed=default

- 在输出后告知"已按Excel生成，如需飞书多维表格版本可随时告诉我"

## 背景与数据来源

本skill基于真实硬件项目的完整WBS数据和实战经验提炼。 源项目计划工时115h，实际工时145h，超期26%。其中EVT超期45%、PVT超期72%。 这些真实数据构成了排期估算和风险预警的知识基础。

## 不适用场景（能力边界）

**本skill适用于：**  硬件产品开发项目（含结构件、电子件、模具、PCBA、EVT/DVT/PVT验证流程）

**本skill不适用于：**

- ❌ 纯软件开发项目（无模具/PCBA/硬件验证阶段，请用敏捷开发排期工具）

- ❌ 纯算法/AI模型项目（无物理实体，无模具/量产环节）

- ❌ 纯供应链/采购项目（无开发阶段，只有采购交付）

- ❌ 已量产产品的维护迭代（无完整EVT/DVT/PVT流程）

- ❌ 海外认证专项（可识别认证需求，但认证周期因国家差异大，需单独排期）

- ⚠️ 半硬件半软件项目：硬件部分可用本skill，软件部分需另排

如果不确定是否适用，先问用户："你的项目有没有模具开发、PCBA设计、EVT/DVT/PVT这些硬件验证阶段？"，有则可用。

## 核心能力

1. **WBS自动拆解** ：输入项目参数，按标准硬件开发流程（立项→ID→EVT→DVT→PVT→MP）自动生成任务拆解

2. **工时智能估算** ：基于基准工时+产品类型调整+团队规模调整，输出各阶段工时估算

3. **日期公式联动** ：Excel中日期用WORKDAY函数联动，插入/删除任务行后后续日期自动顺延

4. **并行任务与关键路径** ：标识串行/并行任务，标记关键路径上的任务

5. **风险预警** ：标注每个阶段的高危/中危/低危风险点，附真实案例参考

6. **评审checkpoint** ：每个阶段输出明确的出口标准和验收清单

7. **跨表关联** ：风险表阶段与排期表联动，评审清单日期引用排期表

8. **双输出格式** ：支持Excel（离线/单人）和飞书多维表格（团队协作/甘特图）

## 首次使用引导问卷

**重要：**  用户第一次使用时，不要急于输出排期表。先通过以下问卷收集完整信息，确保排期结果可用。

### 引导问卷（必问6项）

AI在生成排期前，必须向用户确认以下6个问题。如果用户已主动提供，确认即可；如果缺失，逐项询问：

| 序号 | 问题 | 为什么需要 | 示例回答 |
|---|---|---|---|
| Q1 | 项目名称是什么？ | 用于输出文件命名和表头 | "TWS蓝牙耳机" |
| Q2 | 产品属于哪种复杂度？ | 影响模具/测试/认证周期 | "精密消费电子" |
| Q3 | 产品带哪些特殊模块？ | 影响阶段权重调整 | "蓝牙+ANC算法+锂电池+包装" |
| Q4 | 团队有几个人？分别什么角色？ | 影响工期系数和风险等级 | "PM+硬件+结构+嵌入式+算法，5人" |
| Q5 | 预期什么时候开始？有没有硬性deadline？ | 排期起点和可行性判断 | "8月1日开始，12月底要量产" |
| Q6 | 有没有特殊约束或已知风险？ | 个性化调整排期 | "嵌入式工程师可能中途离职" |

### 问卷使用规则

1. **逐项确认，不要一次抛出所有问题** ：如果用户一句话说了"帮我排智能水杯排期"，先问Q2-Q4（最关键的3个），收到回答后再问Q5-Q6

2. **给选项，不给空白** ：问Q2时直接列出4种复杂度选项让用户选，不要让用户自己想

3. **有默认值但不静默使用** ：即使有默认值，也要告知用户"默认按标准配置估算，你的团队是几个人？"

4. **确认后才生成** ：6个问题全部有答案后才进入排期计算，缺任何一个都先问

5. **不要过度追问** ：如果用户说"就按默认来"，用默认值生成，但在排期概览中标注"⚠️ 团队配置用默认值，实际可能有偏差"

## 使用流程

### Step 1：引导问卷收集输入

按上方"首次使用引导问卷"逐项确认。

**参数清单：**

| 参数 | 必填 | 说明 | 默认值 |
|---|---|---|---|
| 项目名称 | ✅ | 用于输出表头 | - |
| 产品类型 | ✅ | 影响阶段权重调整 | 见下方选项 |
| 产品复杂度 | ✅ | 影响模具/测试/认证周期 | 见下方选项 |
| 预期开始日期 | ✅ | 排期起点 | - |
| 预期结束日期 | ⚠️ | 有则反推工期，无则正向排期 | - |
| 团队配置 | ⚠️ | 影响工期系数和风险等级 | 标准配置（PM+硬件+结构+嵌入式） |
| 是否带算法 | ⚠️ | 决定是否需要算法工程师 | 否 |
| 特殊约束 | ⚠️ | 如"必须某日前量产" | 无 |

**产品类型选项** （可多选）：

- 带无线模块（蓝牙/WiFi/Zigbee等）

- 带算法/AI功能

- 带锂电池

- 带包装零售

- 纯硬件无软件

**产品复杂度选项** （单选）：

- 简单消费电子：结构简单、模具常规、工艺成熟。如保温杯、充电宝、普通小家电

- 精密消费电子：结构紧凑、精密模具、多传感器、有音视频/无线要求。如TWS耳机、智能手表、摄像头

- 医疗设备：需医疗器械注册认证、临床验证、电磁兼容、生物相容性。如监护仪、血压计、血糖仪

- 工业设备：环境适应性要求高（宽温/防尘/防水/防爆）、可靠性要求严、产量小。如工业传感器、网关

**团队配置选项** ：

- 标准配置（3-4人）：PM + 硬件 + 结构 + 嵌入式，可并行工作

- 小项目兼职PM（2-3人）：PM由硬件或结构工程师兼任

- 带算法的完整配置（4-5人）：PM + 硬件 + 结构 + 嵌入式 + 算法

- 缺算法由嵌入式兼任：⚠️高危，EVT和PVT风险翻倍

- 1-2人极小团队：一人多岗，不推荐用于复杂项目

### Step 2：加载知识库

读取 `data/wbs_knowledge_base.json`，获取：

- 6个标准阶段的基准工时和权重

- 各阶段子任务清单

- 产品类型调整系数（无线/算法/电池/包装）

- 产品复杂度调整系数（简单消费/精密消费/医疗/工业）

- 标准团队角色配置和团队调整系数

- 全局规则和风险点

### Step 3：计算排期

计算逻辑：

```
基础工时 = 各阶段基准工时 × 产品类型调整系数 × 产品复杂度调整系数 × 团队配置调整系数
总工时 = 基础工时 × 1.15（buffer系数）
各阶段工期 = 基础工时 / 团队并行度（标准配置按5h/天折算）
```
产品复杂度对排期的影响：

- 简单消费电子：模具常规、测试简单，ID/EVT/DVT/PVT均×0.85-0.90

- 精密消费电子：精密模具2-3轮修模、测试项多，ID×1.20、EVT×1.25、DVT×1.30、PVT×1.20

- 医疗设备：认证周期长（注册检验4-8周）、临床验证不可控，EVT×1.40、DVT×1.60、PVT×1.50

- 工业设备：宽温/防护/可靠性测试周期长，EVT×1.30、DVT×1.40、PVT×1.20

团队配置对排期的影响：

- 标准配置（PM+硬件+结构+嵌入式）：各角色可并行，基准工期

- 带算法完整配置：算法与嵌入式并行，总工期×0.95

- 缺算法由嵌入式兼任：嵌入式变串行瓶颈，总工期×1.25，且EVT/PVT风险等级自动上调

- 小项目兼职PM：PM精力分散，总工期×1.1

- 1-2人极小团队：一人多岗严重串行，总工期×1.4

如果用户给了预期结束日期，反推检查是否可行：

- 总工期 > 可用时间 → 标红警告，建议增加人力或调整范围

- 总工期 ≤ 可用时间 → 正常输出

### Step 4：确认输出格式

排期计算完成后，**主动询问用户选择输出格式** ：

排期已计算完成，输出为哪种格式？

**A. Excel文件（.xlsx）**  — 适合单人使用，离线可用，日期公式联动，零门槛 **B. 飞书多维表格**  — 适合团队协作，内置甘特图视图，跨表双向关联，多人同时编辑

| 维度 | Excel | 飞书多维表格 |
|---|---|---|
| 单人使用 | ✅ 最方便 | ⚠️ 需飞书账号 |
| 团队协作 | ❌ 文件来回传 | ✅ 多人同时编辑 |
| 甘特图视图 | ❌ 需另行做 | ✅ 内置甘特视图 |
| 日期公式联动 | ✅ WORKDAY函数 | ⚠️ 公式字段较弱 |
| 跨表关联 | ❌ 手动筛 | ✅ 关联字段双向联动 |
| 离线使用 | ✅ 完全离线 | ❌ 需联网 |
| 上手门槛 | ✅ 零门槛 | ⚠️ 需了解多维表格 |

**默认选择** ：如果用户不指定，默认输出Excel（零门槛，人人可用）。

**飞书多维表格输出说明** ：

- 如果用户选择飞书多维表格，AI需引导用户提供飞书账号信息

- 多维表格通过API创建，归属在bot空间，需手动共享给用户

- 创建后AI输出共享链接，用户点击即可查看和编辑

- 多维表格支持：甘特图视图、看板视图、日历视图、表格视图

### Step 5：生成输出

#### Excel输出

调用 `scripts/generate_excel.py` 生成Excel文件，输出路径为当前工作目录下 `{项目名称}_项目排期.xlsx`。

**Excel文件包含5个工作表：**

##### Sheet 1：项目概览

- 项目名称、产品类型、产品复杂度、团队配置

- 总工时、总工期、各阶段工时占比

- 关键里程碑日期（V1.1.6起：日期=公式引用WBS排期表里程碑行，排期调整自动联动；附达成条件）

- 排期可行性判断（是否满足预期结束日期）

- 使用说明（8条操作指引）

##### Sheet 2：WBS排期表

列定义：

| 列名 | 说明 |
|---|---|
| 阶段 | 立项会/ID设计/EVT/DVT/PVT/MP |
| 子任务 | 具体任务名；里程碑任务自动加「▲」标识（V1.1.6） |
| 计划工时(h) | 估算工时（里程碑=0） |
| 计划开始 | **Excel公式** （WORKDAY联动+避开法定假日，插入/删除行后自动顺延） |
| 计划结束 | **Excel公式** （=WORKDAY(计划开始, 工期天数-1)；里程碑=计划开始同日） |
| 工期(天) | **Excel公式** （=计划结束-计划开始+1；里程碑固定0） |
| 任务类型 | 串行/并行（下拉框选择） |
| 来源类型 | 内部开发/外协采购（下拉框，V1.1.6新增） |
| 关键路径 | 是/否（关键路径任务红色加粗显示） |
| 前置任务行 | 前置任务名，支持依赖语法：`FS+lag:任务名` / `SS+lag:任务名` / `FF+lag:任务名`（V1.1.6，不写类型默认FS） |
| 责任人 | 角色占位（PM/硬件/结构/嵌入式/算法） |
| 出口标准 | 该任务完成的判定条件；里程碑此处=达成条件（必填） |
| 状态 | 未开始/进行中/已完成/已延期/已取消（下拉框） |
| 实际工时(h) | 空白，项目执行时填写 |
| 实际开始 | 空白，项目执行时填写 |
| 实际结束 | 空白，项目执行时填写 |
| 延期说明 | 空白，项目执行时填写 |

**日期公式联动说明：**

- 所有WORKDAY公式均带「节假日」表引用参数，自动避开中国法定假日（V1.1.6）

- 首行任务的「计划开始」= 项目开始日期

- 串行任务的「计划开始」= WORKDAY(上一行计划结束, 1)

- 并行任务的「计划开始」= 上一行计划开始（同天开始）

- 依赖语法（V1.1.6）：`FS+lag:任务名`=前置结束+1+lag个工作日开始（不写默认FS+0，兼容旧数据）；`SS+5:硬件设计`=与硬件设计开始错峰5个工作日；`FF-2:任务名`=结束与前置结束-2天对齐、开始按工期反推

- 里程碑任务（任务性质=里程碑）：0工期节点、▲标识、结束=开始同日、日期随前置任务自动联动；出口标准（达成条件）必填，缺失时脚本警告并占位「待填写达成条件」

- 内外协分流（V1.1.6）：来源类型=内部开发 → 无工期天时按工时÷5h换算；来源类型=外协采购 → 直接填「工期天」按工作日计算（如模具T1=25天、PCB打板=7天），外协周期由供应商产能决定，不做工时换算

- 用户在Excel中插入新任务行后，填写工期天数，后续所有日期自动顺延

格式要求：

- 阶段名用底色区分（立项会灰、ID蓝、EVT橙、DVT黄、PVT绿、MP灰）

- 计划开始/结束列设为日期格式 YYYY-MM-DD

- 关键路径任务红色加粗

- 冻结首行+前三列（阶段/子任务/工时），方便横向滚动

- 状态/任务类型/关键路径列加数据验证下拉框

##### Sheet 3：风险预警表

列定义：

| 列名 | 说明 |
|---|---|
| 风险等级 | 🔴高危/🟡中危/🟢低危 |
| 风险描述 | 具体风险点 |
| 发生阶段 | **下拉框** （立项会/ID设计/EVT/DVT/PVT/MP/跨阶段），与排期表阶段联动 |
| 发生概率 | >50%/30-50%/<30% |
| 影响范围 | 对哪些任务/阶段产生影响 |
| 真实案例 | 参考项目的实际经历 |
| 缓解措施 | 建议的预防/应对方案 |
| 责任人 | 谁负责跟踪这个风险 |
| 状态 | 未处理/已缓解/已发生/已关闭（下拉框） |

格式要求：

- 高危行整行标红底色

- 中危行整行标黄底色

- 低危行整行标绿底色

- 按风险等级排序：高危→中危→低危

- 「发生阶段」列加数据验证下拉框，用户可快速筛选某个阶段的风险

##### Sheet 4：评审Checkpoint清单

列定义：

| 列名 | 说明 |
|---|---|

## 硬件项目标准阶段说明

### 立项会（KICKOFF）

- 基准工时：4h

- 占比：3.5%

- 典型工期：3天

- 核心任务：立项申请书、PRD

- 出口标准：立项通过、PRD核心需求确认

### ID设计（ID）

- 基准工时：15h

- 占比：13%

- 典型工期：15天

- 核心任务：需求沟通→ID设计→初稿评审→修改→终稿→定稿

- 出口标准：ID终稿评审通过、可输出给结构工程

### EVT（工程验证）

- 基准工时：40h

- 占比：35%（实际常超至40%）

- 典型工期：40天

- 核心任务：关键器件寻源、硬件设计、结构设计MD、嵌入式软件开发、EVT组装测试、包装设计

- **延期重灾区，超期40-50%是常态**

- 出口标准：样机能开机、核心功能可用、关键电气性能验证通过

- 并行任务：硬件设计、结构设计、嵌入式开发通常并行进行

### DVT（设计验证）

- 基准工时：33h

- 占比：29%

- 典型工期：35天

- 核心任务：开模、PCBA备料、软件开发、DVT组装、DVT测试

- 出口标准：T0试模OK、DVT测试通过、BOM冻结

- 并行任务：开模与PCBA备料并行，软件开发与模具修模并行

### PVT（生产验证）

- 基准工时：18h

- 占比：16%（实际常超至21%）

- 典型工期：20天

- 核心任务：
