# 投产缺口分析与下单倒排助手

投产前把「BOM × 库存 × 在途」三张表对一遍，告诉你：现在缺什么、缺多少、哪些在途能指望、哪些料再不下单就来不及——以及哪些对齐是机器拿不准的，交给你人工确认，绝不静默拍板。

**适用对象** ：用 Excel / 轻量进销存管库存的中小硬件团队。已有完整 MRP/MES 的公司请直接用系统跑 MRP，本工具不适用。

**诚实边界（先读这个）** ：

- 输入只用你手里现成的三张表导出，不需要为本工具维护任何新数据；

- 用完即走：不存状态、不跟踪、不做台账；

- **输出永远不承诺到货** ——一切日期基于下单要求日/类目参考值估算，供应商最新承诺在他们微信和电话里，AI 够不到，关键缺料请走报告里的「ETA 人工核实清单」。

## 快速开始

### 第1步：导出三张表（CSV 优先）

| 表 | 必需列 | 说明 |
|---|---|---|
| BOM | 料号、单台用量（描述/MOQ可选） | 你设计端的 BOM 导出 |
| 库存 | 料号、数量 | 进销存/Excel 库存表导出 |
| 采购单 | 料号、采购数量（要求到货日可选） | 在途 PO 导出；没有 PO 表可跳过 |

列名不要求和示例完全一致，脚本按常见列名自动识别（中英文别名，前5行内认表头）。完整别名表见 `references/input-formats.md`。

### 第2步：一键分析

```
python3 scripts/gap_analysis.py analyze \
  --bom examples/bom.csv --inventory examples/inventory.csv \
  --po examples/po.csv --batch 50 --loss 2 \
  --build-date 2026-10-15 --out-dir gap_output
```
- `--batch` 本批投产台数；`--loss` 损耗率%（可省）；

- `--build-date` 投产日期（倒排起点）；`--buffer-days` 下单缓冲（默认7天）。

输出 5 个文件（`gap_output/`）：`gap_report.md`（主报告）、`gaps.csv`（缺口表）、`aligned.csv`（对齐明细）、`review_low_confidence.csv`（待人工确认清单）、`gap_analysis.json`（结构化结果）。

### 第3步：处理"待人工确认"行

中低置信的对齐**已从缺口计算中剔除** 并列入 `review_low_confidence.csv`。逐条确认后，把确认关系写成两列 CSV（`bom料号,库存料号`），用 `--map` 重跑即自动补上：

```
python3 scripts/gap_analysis.py analyze --bom ... --inventory ... --po ... \
  --batch 50 --build-date ... --map my_map.csv --out-dir gap_output
```
## 三层缺口结构（任何层不静默消失）

1. **可确认在途** ：采购单上有「要求到货日」→ 进时间线、计入缺口计算，投产日前才到的才扣减；

2. **在途未确认** ：已下单但没有要求到货日 → 报告单独列出（可见但**不计入** 计算），建议找采购补要求日；

3. **净缺口清单** ：扣完账面库存与可确认在途后的真缺口，按紧迫度排序，含建议下单量（自动对齐 MOQ）。

另外还有第 4 张清单：**未对齐/待人工确认** （未计入计算，确认后 --map 重跑）。

## 下单倒排怎么读

- 提前期两层来源：你的历史 PO（下单日+要求到货日可推算实际值）优先，否则用类目参考区间（IC/MCU 8-16 周、晶振/屏 6-10 周、连接器 4-8 周、结构件/注塑 15-30 天等，完整表见 `references/lead-times.md`）；

- 最晚下单日（保守）= 投产日 − 提前期上限 − 缓冲；乐观值用提前期下限；

- 状态判定：已超期→**今天就得下单/催单** ；进入窗口→尽快下单；否则显示剩余缓冲天数；

- 类目参考值是行业经验区间，报告里永远标注来源与"以供应商确认为准"。

## 触发方式

| 用户说 | 做什么 |
|---|---|
| 投产前看看缺什么料 / 齐套率怎么样 | analyze（三表全流程） |
| 只有 BOM 和库存，没有 PO | analyze 不带 --po（无在途层也能跑） |
| 这两个料号系统里对不上 | align 先看对齐明细，确认后填 --map |
| 缺口清单有了，帮我倒排下单日 | countdown（对 gaps.csv 单独倒排） |
| 这料到底该信哪个交期 | 读 lead-times.md 并解释"历史PO实际 > 类目参考 > 通用兜底"的覆盖关系 |

## 示例对话

**用户** ：下周要投 50 台智能插座 X1，帮我看看缺什么料（附三张 CSV） **助手** ：跑 analyze → "需求50台（含2%损耗）：净缺口1项（外壳下盖，建议按MOQ下单50）；在途里 TYPE-C连接器 200pcs 没填要求到货日，已列入'在途未确认'不计入计算；另有3行料号没对上，在待人工确认清单里，确认后我重跑。"并提醒账面库存未盘、关键料建议抽盘。

**用户** ：缺的料最晚什么时候下 PO？ **助手** ：按每个缺口料的类目提前期/历史PO实际值给保守+乐观两个最晚下单日，标注"估算，以供应商确认为准"，并生成 ETA 人工核实清单让采购去对供应商拿最新承诺。

## 设计红线（为什么它"笨"得诚实）

1. **不承诺到货** ：所有日期是估算参考，报告头部质量声明块固定声明数据截至时间、账实差异风险、在途与交期假设；

2. **不静默决策** ：低置信对齐一律转人工清单，绝不硬凑数字；

3. **用完即走** ：无状态、无提醒、无台账，输出目录随用随删；

4. **不替代 MRP** ：目标用户是轻量进销存/Excel 管库存的团队，有完整 MRP/MES 的公司请用系统。
